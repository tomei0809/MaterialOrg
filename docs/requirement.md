# 要件定義書：Material Organization

## 1. プロジェクト概要

### 1.1 プロジェクト名

Material Organization（講義資料一元管理 Web アプリ）

### 1.2 背景・課題

大学の講義資料、配布された PDF、撮影したプリント、個人のノートなどが、自宅 PC、学校のノート PC、スマートフォンに分散している。

そのため、必要な資料を探す際に複数の端末や保存場所を確認する必要があり、資料の整理や検索に時間がかかる。

### 1.3 目的

講義資料とその関連情報を一元管理し、端末や保存場所を意識せずに資料を登録・整理・検索・閲覧できる Web アプリを開発する。

### 1.4 想定ユーザー

開発者本人を主な利用者とする。

初期段階では不特定多数への公開や、複数ユーザー間での資料共有を目的としない。

## 2. 解決したい課題

- 資料が複数の端末やフォルダに分散している。
- ファイル名だけでは資料の内容が分からない。
- 必要な資料を探すために複数の保存場所を確認する必要がある。
- 講義・学期・単元ごとに資料を整理する手間がかかる。
- 外出先やスマートフォンから資料を確認しにくい。

## 3. 機能要件

分類は、利用者が自由に作れる「フォルダ」（最大5階層）で行う。当初の設計にあった「科目」の管理は、フォルダで置き換えたため設けない。

### 3.1 資料登録

- PDF・画像・動画・音声・Office・コード・テキスト・ZIP のファイルを登録できる（1ファイル 500MB まで）。
- 複数のファイルをドラッグ＆ドロップでまとめて登録できる。
- タイトル（必須）、種類（必須：講義スライド・課題・過去問・ノート・その他）、フォルダ、説明、タグ（10個まで）を設定できる。
- 必須項目が未入力の場合や、許可していない形式・サイズのファイルはエラーを表示して保存しない。

### 3.2 整理（フォルダ・まとめ・タグ）

- フォルダを作成・名前の変更・色の変更・削除できる。フォルダの中にフォルダを作れる（5階層まで）。
- フォルダはドラッグで並び替え、別のフォルダの中へ移せる。
- フォルダを削除しても資料は消えず、1つ上のフォルダ（最上位なら未分類）へ移る。
- 資料をドラッグしてフォルダへ移せる。複数を選んでまとめて移せる。
- 複数の資料を「まとめ」として1行に束ね、その中の並び順を変えられる。
- タグを付けて、タグで絞り込める。

### 3.3 資料一覧・資料マップ

- 登録済み資料を一覧表示できる（1〜3列、フォルダごとの区切り）。
- 一覧の上に「資料マップ」を表示し、どのフォルダにどの種類の資料がどれだけあるかを面積で示す。
- 資料が存在しない場合は、その旨と登録の方法を表示する。

### 3.4 検索・絞り込み・並び替え

- タイトル・フォルダ名・タグ・説明で検索できる。直近の検索語を8件まで再表示する。
- 種類・フォルダ・タグで絞り込める。お気に入り・最近使った資料・最近追加・未分類を表示できる。
- 更新日・登録日・タイトルなどで並べ替えられる。
- 検索結果が0件の場合は、その旨を表示する。

### 3.5 閲覧

- マウスを乗せると資料のプレビューを表示する（PDF のスライドショー、動画の無音再生、コードの自動スクロールなど）。
- ページを離れずに、画面全体のビューアで資料を閲覧できる。
  - PDF・画像の拡大・移動、PDF のページ移動
  - コード・テキスト・Markdown・CSV・ipynb の整形表示と検索
  - Word・PowerPoint・Excel の内容、ZIP の中身
  - 動画・音声の再生（速度変更・位置の移動）
- 元のファイルを新しいタブで開く・保存できる。

### 3.6 編集・削除・復元

- 登録済み資料のタイトル、種類、フォルダ、説明、タグ、ファイルを変更できる。
- 資料を削除するとゴミ箱へ移り、30日間は元のフォルダへ戻せる。削除の直後は通知から取り消せる。
- ゴミ箱から完全に削除できる。30日を過ぎた資料は自動で完全に削除する（添付ファイルも削除する）。

### 3.7 複数端末からの利用

- PC とスマートフォンのブラウザから利用できる。
- 同じデータベースとファイル保存先を参照する。
- スマートフォンで撮影した画像を登録できる。

### 3.8 ログインとアクセス制御

- メールアドレスとパスワードで新規登録・ログイン・ログアウトできる（登録できる人数には上限を設ける）。
- 数人がそれぞれ自分の教材を管理できる。教材・フォルダ・まとめ・タグ・添付ファイルは本人だけが見られ、ほかの利用者とは共有しない。
- ログイン中はパスワードを変更できる。忘れたときは、メールのリンクから再設定できる。
- 他人の資料の ID や添付ファイルの URL を知っても、取得・変更できない。

## 4. 非機能要件

### 4.1 操作性

- PC とスマートフォンの画面幅に対応する。ライト／ダーク表示に対応する。
- ドラッグ＆ドロップ、右クリックメニュー、キーボード操作（/・N・Space・F・F2・Delete など）で素早く操作できる。
- 入力エラーや通信エラーが発生した場合は、利用者が原因を把握できるメッセージを表示する。

### 4.2 セキュリティ

- パスワードや秘密鍵などをソースコードに直接記載しない。環境変数で管理する。
- ファイル形式・サイズ・入力値をサーバー側で検証する。
- 本番の添付ファイルは非公開の S3 バケットに置き、Rails を通して配信する。
- HTTPS を利用できる公開環境にデプロイする。

### 4.3 保守性

- フロントエンド（Next.js）とバックエンド（Rails API）を分離する。
- データベースの構造変更をマイグレーションで管理する。
- 主要な API とモデルにテストを用意し、GitHub Actions で自動実行する。
- GitHub でソースコードと変更履歴を管理する。

### 4.4 データ管理

- ファイル本体と資料の管理情報を区別する（Active Storage）。
- 削除はまずゴミ箱へ移し、誤削除から30日間は復元できるようにする。

## 5. 使用技術

| 分類 | 技術 |
|---|---|
| バックエンド | Ruby on Rails 8.1（API） |
| フロントエンド | Next.js 16（App Router）・React 19 |
| フロントエンド言語 | TypeScript |
| スタイル | Tailwind CSS v4 |
| データベース | PostgreSQL |
| ファイル管理 | Active Storage |
| ファイル保存 | 開発：ローカルディスク／本番：Amazon S3 |
| 本番環境 | Vercel（Next.js）・Render（Rails）・Neon（PostgreSQL） |
| バージョン管理 | Git・GitHub |
| 自動テスト・CI | Minitest・RuboCop・Brakeman・ESLint・TypeScript・GitHub Actions |

## 6. 対象外（今後の候補）

- 複数の利用者での資料の共有
- OCR による画像内文字の認識、PDF の全文検索
- AI による資料要約や問題生成
- リアルタイム共同編集
- 独自のモバイルアプリ

## 7. 完成条件

- PDF・画像などの資料を登録できる。
- 資料情報をデータベースに保存できる。
- フォルダ・まとめ・タグで資料を整理できる。
- 検索と条件による絞り込みができる。
- 資料をページ内で閲覧できる。
- 資料情報を編集・削除・復元できる。
- PC とスマートフォンのブラウザで主要操作を実行できる。
- 不正な入力やファイルをサーバー側で拒否できる。
- README に環境構築方法と起動方法を記載する。
