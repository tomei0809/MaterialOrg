# 要件定義書：Material Organization

## 1. プロジェクト概要

### 1.1 プロジェクト名

Material Organization（講義資料一元管理Webアプリ）

### 1.2 背景・課題

大学の講義資料、配布されたPDF、撮影したプリント、個人のノートなどが、自宅PC、学校のノートPC、スマートフォンに分散している。

そのため、必要な資料を探す際に複数の端末や保存場所を確認する必要があり、資料の整理や検索に時間がかかる。

### 1.3 目的

講義資料とその関連情報を一元管理し、端末や保存場所を意識せずに資料を登録・整理・検索・閲覧できるWebアプリを開発する。

### 1.4 想定ユーザー

開発者本人を主な利用者とする。

初期段階では不特定多数への公開や、複数ユーザー間での資料共有を目的としない。

## 2. 解決したい課題

- 資料が複数の端末やフォルダに分散している。
- ファイル名だけでは資料の内容が分からない。
- 必要な資料を探すために複数の保存場所を確認する必要がある。
- 科目や講義回ごとに資料を整理する手間がかかる。
- 外出先やスマートフォンから資料を確認しにくい。

## 3. 機能要件

### 3.1 資料登録

- PDFファイルおよび画像ファイルを登録できる。
- タイトル、科目、講義日、資料種別、説明、タグを設定できる。
- 登録した資料情報とファイルを関連付けて保存する。
- 必須項目が未入力の場合はエラーを表示する。
- 許可していないファイル形式やサイズのファイルは拒否する。

### 3.2 資料一覧

- 登録済み資料を一覧表示できる。
- タイトル、科目、講義日、資料種別を表示する。
- 資料が存在しない場合は、その旨を表示する。
- 資料の詳細画面へ移動できる。

### 3.3 資料検索・絞り込み

- タイトルで資料を検索できる。
- 科目で資料を絞り込める。
- 資料種別で資料を絞り込める。
- 講義日または登録日時を基準に並べ替えられる。
- 検索結果が0件の場合は、その旨を表示する。

### 3.4 資料詳細・閲覧

- 資料の詳細情報を確認できる。
- PDFまたは画像をブラウザ上で閲覧できる。
- 必要に応じて元ファイルをダウンロードできる。

### 3.5 資料編集・削除

- 登録済み資料のタイトル、科目、講義日、説明、資料種別、タグを変更できる。
- 資料を削除できる。
- 削除前に確認を表示する。
- 資料情報と関連ファイルの削除が整合するようにする。

### 3.6 科目管理

- 科目を登録できる。
- 科目一覧を表示できる。
- 科目名を変更できる。
- 資料登録時に所属科目を選択できる。

### 3.7 複数端末からの利用

- PCとスマートフォンのブラウザから利用できる。
- 同じデータベースとファイル保存先を参照する。
- スマートフォンから撮影した画像を登録できる。

### 3.8 アクセス制御

- 公開環境では、許可された利用者だけが資料を閲覧・変更できる構成とする。
- 認証・認可を実装するまでは、機密性のある資料を公開環境に保存しない。
- 他の利用者が資料IDを推測してアクセスしても、権限のない資料を取得できないようにする。

## 4. 非機能要件

### 4.1 操作性

- PCとスマートフォンの画面幅に対応する。
- 資料の登録から検索・閲覧まで、複雑な操作を必要としない。
- 入力エラーや通信エラーが発生した場合は、利用者が原因を把握できるメッセージを表示する。

### 4.2 セキュリティ

- パスワードや秘密鍵などをソースコードに直接記載しない。
- 環境変数などを使用して接続情報を管理する。
- ファイル形式・サイズ・入力値をサーバー側で検証する。
- 認証・認可を適切に実装する。
- HTTPSを利用できる公開環境にデプロイする。

### 4.3 保守性

- フロントエンドとバックエンドを分離する。
- データベースの構造変更をマイグレーションで管理する。
- 主要なAPIとデータ処理にテストを用意する。
- GitHubでソースコードと変更履歴を管理する。

### 4.4 データ管理

- ファイル本体と資料の管理情報を区別する。
- データベースにファイルの保存先や添付情報を記録する。
- バックアップや復旧方法を検討する。

## 5. 使用技術

| 分類                       | 技術                              |
| -------------------------- | --------------------------------- |
| バックエンド               | Ruby on Rails（API）              |
| フロントエンド             | React                             |
| フロントエンド言語         | TypeScript                        |
| データベース               | PostgreSQL                        |
| ファイル管理               | Active Storage                    |
| 開発時のファイル保存       | ローカル保存                      |
| 本番環境のファイル保存候補 | Amazon S3                         |
| バージョン管理             | Git・GitHub                       |
| 自動テスト・CI             | RSpec、GitHub Actionsを候補とする |

## 6. 初期開発の対象外

- OCRによる画像内文字の認識
- PDFの全文検索
- AIによる資料要約や問題生成
- 複数ユーザー間の資料共有
- リアルタイム共同編集
- 高度なアクセス分析
- 独自のモバイルアプリ

## 7. 完成条件

- PDF・画像を登録できる。
- 資料情報をデータベースに保存できる。
- 科目別に資料を整理できる。
- タイトル検索と条件による絞り込みができる。
- 資料の詳細を表示し、ファイルを閲覧できる。
- 資料情報を編集・削除できる。
- PCとスマートフォンのブラウザで主要操作を実行できる。
- 不正な入力やファイルをサーバー側で拒否できる。
- 公開する場合は、認証・認可を実装し、許可された利用者だけが資料にアクセスできる。
- READMEに環境構築方法と起動方法を記載する。

## 8. 開発方針

まず資料登録・一覧表示・検索・閲覧の一連の流れを完成させる。その後、編集・削除、アクセス制御、テスト、デプロイを順番に進める。

機能を追加する場合は、初期開発の完成条件を満たした後に優先度を判断する。
