# 画面設計：Material Organization

> **現行実装との差異（2026-10-24 時点）**
> この文書は実装前の当初設計です。現在の実装では「科目（subjects）」は廃止し、分類はフォルダ（階層化可能）で行います。
> 教材は `materials` テーブル（title / material_type / description / folder_id / bundle_id ＋添付ファイル・タグ）、API は `/api/v1/materials`・`/api/v1/folders`・`/api/v1/bundles`・`/api/v1/tags` です。
> 最新の仕様は `backend/db/schema.rb` と `backend/config/routes.rb` を参照してください。

## 1. 画面一覧

| 画面ID | 画面名   | パス                | 主な機能               |
| ------ | -------- | ------------------- | ---------------------- |
| SCR-01 | 資料一覧 | /documents          | 一覧・検索・絞り込み   |
| SCR-02 | 資料登録 | /documents/new      | 資料とファイルの登録   |
| SCR-03 | 資料詳細 | /documents/:id      | 詳細情報・ファイル閲覧 |
| SCR-04 | 資料編集 | /documents/:id/edit | 資料情報の変更         |
| SCR-05 | 科目管理 | /subjects           | 科目の一覧・登録・変更 |

## 2. SCR-01 資料一覧

### 表示要素

- アプリ名
- 資料登録ボタン
- 検索入力欄
- 科目選択
- 資料種別選択
- 並べ替え選択
- 資料一覧
- 検索結果件数

### 資料一覧の項目

- タイトル
- 科目名
- 資料種別
- 講義日
- 登録日時
- 詳細画面へのリンク

### 操作

- 検索文字列を入力すると資料を検索する。
- 科目や資料種別を選択すると結果を絞り込む。
- 資料を選択すると詳細画面に移動する。
- 登録ボタンを押すと資料登録画面に移動する。

## 3. SCR-02 資料登録

### 入力項目

- タイトル（必須）
- 科目（必須）
- 資料種別（必須）
- 講義日（任意）
- 説明（任意）
- タグ（任意）
- ファイル（必須）

### 操作

- 登録ボタンで資料を保存する。
- キャンセルボタンで一覧画面に戻る。
- 入力エラー時は該当項目のエラーを表示する。
- 登録成功時は詳細画面または一覧画面に遷移する。

## 4. SCR-03 資料詳細

### 表示項目

- タイトル
- 科目名
- 資料種別
- 講義日
- 説明
- タグ
- 登録日時・更新日時
- 添付ファイル名

### 操作

- PDFまたは画像を表示する。
- ファイルをダウンロードする。
- 編集画面へ移動する。
- 削除ボタンを押すと確認ダイアログを表示する。

## 5. SCR-04 資料編集

### 入力項目

資料登録画面と同様。ただし、現在の情報を初期値として表示する。

### 操作

- 保存ボタンで更新する。
- キャンセルボタンで詳細画面に戻る。
- ファイルを変更する場合は新しいファイルを指定する。

## 6. SCR-05 科目管理

### 表示項目

- 科目名
- 年度
- 学期
- 科目に属する資料数

### 操作

- 科目を登録する。
- 科目名や年度・学期を変更する。
- 資料が存在する科目の削除はできないようにする。

## 7. 共通仕様

- PCとスマートフォンの画面幅に対応する。
- 通信中は読み込み状態を表示する。
- 通信失敗時はエラーメッセージを表示する。
- 検索結果が0件の場合は、該当資料がないことを表示する。
- 削除前には確認ダイアログを表示する。
- ボタンやフォームには分かりやすいラベルを付ける。
- バックエンドの入力検証エラーを画面に表示する。

## 8. 画面遷移

```text
資料一覧
  ├── 資料登録 → 資料一覧または資料詳細
  ├── 資料詳細
  │     ├── 資料編集 → 資料詳細
  │     └── 資料削除 → 資料一覧
  └── 科目管理
```

## 9. 初期開発での画面設計方針

見た目の作り込みよりも、資料登録・検索・閲覧を迷わず行えることを優先する。UIライブラリを採用する場合も、画面構成と操作の一貫性を維持する。
